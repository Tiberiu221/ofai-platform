# OFAI Audit #9 — Full Project Audit

**Data:** 6 Martie 2026
**Scope:** Backend, Flutter, Web Frontend, Database, Config & Infra, Subscription & Billing
**Metoda:** 6 agenți de audit în paralel
**Total findings (deduplicate):** 22 CRITICAL, 30 HIGH, 38 MEDIUM, 30 LOW = **120 unice**

---

## REZUMAT EXECUTIV

Auditul #9 a identificat **120 probleme unice** (după deduplicare din 155 raw findings). Cele mai grave clustere sunt:

1. **Stripe webhook handlers gol** — plățile se colectează dar subscripțiile nu se creează în DB
2. **Banned users bypass** — utilizatorii banați păstrează acces pe web portal (4 middleware-uri afectate)
3. **XSS vectori multipli** — `javascript:` URI injection, innerHTML fără escape, textarea breakout
4. **Schema incompletă** — tabele/coloane lipsă din `src/migrations/`, conflicte între cele 2 directoare
5. **Tier gating fail-open** — erori DB permit acces la features premium

## CRITICAL (22)

---

### CRIT-01: Stripe webhook handlers sunt no-ops — plățile nu creează subscripții
**Sursa:** Backend, Subscription, Config
**Fișier:** `src/routes/billing.js:105–134`
**Impact:** Revenue loss — Stripe colectează bani dar `business_subscriptions` nu se creează niciodată. Badge sync nu rulează. Cron expiry nu are ce expira.
**Fix:** Implementare completă a tuturor 5 handler-elor înainte de activarea Stripe keys.

### CRIT-02: Banned users trec web auth — `webAuth.js` nu verifică `banned_at`
**Sursa:** Backend
**Fișier:** `src/middleware/webAuth.js:68–74`
**Impact:** Utilizatorii banați pot accesa tot portalul web, contul, și funcționalitățile autentificate.
**Fix:** Adăugare `banned_at` în SELECT și verificare `if (user.banned_at) return null`.

### CRIT-03: `businessUserAuth` nu verifică `banned_at`
**Sursa:** Backend
**Fișier:** `src/middleware/businessAuth.js:92–119`
**Impact:** Utilizatorii banați pot lista business-urile proprii pe mobile.
**Fix:** Adăugare `banned_at` la query și reject dacă este setat.

### CRIT-04: `businessWebAuth` nu verifică `banned_at` post-refresh
**Sursa:** Backend
**Fișier:** `src/middleware/businessWebAuth.js:69–76`
**Impact:** Utilizatorii banați continuă să acceseze portalul business până la expirarea cookie-ului.
**Fix:** Adăugare `banned_at` în SELECT la linia 69.

### CRIT-05: `max_reveals` pentru promo coduri nu se verifică la reveal
**Sursa:** Backend
**Fișier:** `src/routes/offers.js:654–689`, `src/routes/web.js:973–1012`
**Impact:** Business owners setează limita dar utilizatorii o pot depăși nelimitat.
**Fix:** Verificare `COUNT(*) FROM code_reveals` vs `max_reveals` înainte de return.

### CRIT-06: Web gallery upload folosește limită hardcoded 8 în loc de tier
**Sursa:** Backend
**Fișier:** `src/routes/web.js:2306–2309`
**Impact:** Premium businesses nu pot folosi mai mult de 8 imagini din web portal (dar pot din mobile).
**Fix:** Înlocuire `>= 8` cu limita din `getBusinessTier()`.

### CRIT-07: Stored XSS via `javascript:` URI — `business.website` și `booking.url`
**Sursa:** Web Frontend
**Fișier:** `src/views/public/business-detail.ejs:140,182,446`, `offer-detail.ejs:993`
**Impact:** Business owner introduce `javascript:...` ca website → XSS persistent pe fiecare vizitator.
**Fix:** Validare server-side că URL-urile încep cu `https://` sau `http://`.

### CRIT-08: XSS via innerHTML — competitive insights din API response
**Sursa:** Web Frontend
**Fișier:** `src/views/public/portal/manage.ejs:2858–2897`
**Impact:** `data.reason`, `ins.metric` din API se injectează neescapate via innerHTML.
**Fix:** Wrapper cu `escapeHtml()` (deja disponibil la linia 2922).

### CRIT-09: XSS — `review.response_text` breakout din `<textarea>`
**Sursa:** Web Frontend
**Fișier:** `src/views/public/portal/manage.ejs:1204`
**Impact:** `</textarea><script>...` breakout posibil.
**Fix:** Sanitizare server-side sau render via JavaScript `textarea.value = ...`.

### CRIT-10: CSRF token lipsă pe `trackClick` — analytics silently failing
**Sursa:** Web Frontend
**Fișier:** `src/views/public/partials/footer.ejs:72–79`
**Impact:** Toate click-urile de analytics (phone, whatsapp, navigate, etc.) returnează 403 și nu se înregistrează.
**Fix:** Adăugare header `X-CSRF-Token`.

### CRIT-11: Google OAuth Client ID hardcoded în Flutter
**Sursa:** Flutter, Config
**Fișier:** `ofai_flutter/lib/core/network/api_endpoints.dart:7`
**Impact:** Client ID baked în binary. Permite impersonare OAuth flows.
**Fix:** Eliminare `defaultValue`, inject doar via `--dart-define`.

### CRIT-12: Flutter `_checkAuth` face logout pe orice eroare non-Dio (inclusiv JSON parse)
**Sursa:** Flutter
**Fișier:** `ofai_flutter/lib/providers/auth_provider.dart:72–74`
**Impact:** Server deployment cu JSON malformat → toți utilizatorii se deloghează.
**Fix:** Catch generic nu ar trebui să seteze starea ca `unauthenticated`.

### CRIT-13: Promo code loading spinner blocat permanent la `null` code
**Sursa:** Flutter
**Fișier:** `ofai_flutter/lib/screens/offer/offer_detail_screen.dart:907–915`
**Impact:** Dacă serverul returnează `promo_code: null`, spinner-ul rămâne infinit.
**Fix:** Setare `_loading = false` indiferent de null/non-null.

### CRIT-14: `_checkAuth()` apelat în constructor — race condition cu router
**Sursa:** Flutter
**Fișier:** `ofai_flutter/lib/providers/auth_provider.dart:42`
**Impact:** Auth status rămâne `initial` pe durata network call → flash de login screen.
**Fix:** Tratare `AuthStatus.initial` ca loading state în router redirect.

### CRIT-15: `attachTier()` fail-open — inline tier checks bypassed pe eroare DB
**Sursa:** Subscription
**Fișier:** `src/middleware/tierAuth.js:21–26`, `web.js:2677`, `business-portal.js:779`
**Impact:** DB error → `req.tier = null` → offer toggle/booking gate bypassed.
**Fix:** Return 503 când `req.tier` este null și gating enabled.

### CRIT-16: No idempotency guard pe webhook handlers
**Sursa:** Subscription
**Fișier:** `src/routes/billing.js:77–101`
**Impact:** Stripe retries pot crea duplicate subscription rows.
**Fix:** Tabel `stripe_processed_events(event_id)` + verificare înainte de procesare.

### CRIT-17: iOS `NSAllowsArbitraryLoads = true` — ATS dezactivat complet
**Sursa:** Config
**Fișier:** `ofai_flutter/ios/Runner/Info.plist:6–9`
**Impact:** App Store rejection risk + trafic HTTP plain pe rețele nesigure.
**Fix:** Eliminare flag sau înlocuire cu `NSAllowsLocalNetworking`.

### CRIT-18: Admin panel — plaintext password via env var, no bcrypt
**Sursa:** Config
**Fișier:** `src/middleware/adminAuth.js:3–4,44–46`
**Impact:** Environment dump expune password-ul admin direct.
**Fix:** Credențiale bcrypt-hashed în DB, cu session-based auth.

### CRIT-19: Schema conflicte — 3 migrații duplicate între `migrations/` și `src/migrations/` (026, 027, 032)
**Sursa:** Database
**Impact:** Fresh install din `src/migrations/` lipsește `is_verified`, `badge_definitions`, `user_badges`, `display_badge_id`.
**Fix:** Creare `046_schema_from_legacy.sql` cu `IF NOT EXISTS` guards.

### CRIT-20: Tabele/coloane lipsă complet din `src/migrations/` — `review_responses`, `review_summaries`, booking columns, `businesses.description`
**Sursa:** Database
**Impact:** Fresh DB install → crash la orice request ce join-ează aceste tabele.
**Fix:** Includere în `046_schema_from_legacy.sql`.

### CRIT-21: Deal-of-Day nomination cron NU e în tranzacție
**Sursa:** Database, Subscription
**Fișier:** `src/services/cronJobs.js:244–258`
**Impact:** Crash parțial → nomination marcată `selected` dar offer fără `is_deal_of_day`.
**Fix:** Wrap în `BEGIN/COMMIT/ROLLBACK`.

### CRIT-22: Migration 009 creează indexuri pe tabele inexistente (`subscriptions`, `favorites`, `offer_locations`) + `ANALYZE` care eșuează
**Sursa:** Database
**Fișier:** `src/migrations/009_performance_indexes.sql:72–77,100–106,132–146`
**Impact:** Fresh install → migration 009 fail, indexuri de după linia 132 rămân neaplicate.
**Fix:** Guard cu `DO $$ BEGIN ... EXCEPTION WHEN undefined_table THEN NULL END $$`.
